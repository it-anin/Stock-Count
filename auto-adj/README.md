# Auto R14.102 + R05.105 → Supabase (ป็อปอัพ 📦 ปรับปรุงสินค้า)

อ่าน `R14.102` (LOT/EXP) กับ `R05.105` (ราคา Price Level 4) ที่ export จาก ProMaxx มาวางในโฟลเดอร์
แล้วเขียนขึ้นตาราง `adj_*` บน Supabase ทุกเช้า — ป็อปอัพ 📦 ปรับปรุงสินค้า ดึงเฉพาะ SKU ที่อยู่ในใบไปเอง
**เภสัช/Supervisor ไม่ต้องแนบไฟล์อีก เปิดป็อปอัพแล้วกด Export ได้เลย** (คอลัมน์ LOT ยังเลือกเองเหมือนเดิม)

## สถานะจริง (12 ก.ย. 2026)

✅ **อัปข้อมูลจริงขึ้น Supabase สำเร็จแล้วครั้งแรก** — รันด้วยมือจากเครื่อง `BIG-IT`:

| ตาราง | จากไฟล์ | ผล |
|---|---|---|
| `adj_r14_lots` | `ADJ_R14.102.CSV` (44 MB · 130,408 แถว) | 35,311 คู่ SKU+LOT · 5,140 SKU |
| `adj_r05_prices` | `ADJ_R05105.CSV` (38,878 แถว) | 6,674 SKU · มีราคาครบทุกตัว |

ตาราง + RLS สร้างแล้ว · รันซ้ำเนื้อหาเดิมได้ผล "ไม่เขียนข้อมูล อัปเดตแค่ `checked_at`" ตามดีไซน์ · parity กับ `index.html` ผ่านทั้งสองไฟล์

⏳ **เหลือ:** ① ไฟล์ `ADJ_R05105.CSV` ยังไม่ถูก export ทุกวัน (ล่าสุด 7 ก.ย.) ② ยังไม่ได้ลงทะเบียน Task `AutoAdjImport`
— ต้องลงบนเครื่องที่ได้ไฟล์**ทั้งสองตัว**ทุกเช้า (บน `BIG-IT` มี `ADJ_R14.102.CSV` สดทุกวันจาก `BOTR14102`) ③ ยังไม่ deploy เว็บ

## ทำไมต้องมี

- เดิมป็อปอัพอ่านไฟล์ในเครื่อง แล้วเก็บไว้เฉพาะ SKU ที่เป็น Stock Adjustment **ณ ตอนแนบ**
  ปุ่ม 💾 บันทึกผลที่กรองแล้วลง Firestore `{branch}_adjlot` ⇒ พอมี SKU ใหม่เข้ามา หรือกด "เริ่มนับใหม่" ต้องแนบใหม่
- ไฟล์ R14.102 มีมากกว่า 200,000 แถว **ใส่ Firestore ไม่ได้** (1 document รับได้ 1 MiB) ⇒ ใช้ Postgres ของ Supabase
  ซึ่งค้นด้วย "SKU อยู่ในรายการนี้" ได้ตรง ๆ

## สิ่งที่เขียนลง Supabase — แบบ "generation"

1. ตั้งเลข `gen` ใหม่จากเวลาปัจจุบัน แล้วใส่แถวทีละ 5,000 (**ผู้ใช้ยังไม่เห็น** เพราะเว็บกรอง `gen = active_gen` เสมอ)
2. นับกลับจาก server ต้องเท่ากับที่ส่ง
3. สลับ `adj_meta.active_gen` เป็น gen ใหม่ — **จุดเผยแพร่จุดเดียว** · ชุดเดิมย้ายไปเป็น `prev_gen`
4. ลบชุดที่เก่ากว่า `prev_gen` (ล้มได้ ไม่ถือเป็นความผิดพลาด — แถวเก่าที่ค้างไม่มีใครเห็น)

ล้มก่อนข้อ 3 = ชุดที่ใช้งานอยู่ไม่ถูกแตะเลย ผู้ใช้ยังเห็นข้อมูลเดิมครบ · สคริปต์ลบแถวของ gen ที่ค้างทิ้งให้
ทุกขั้นเป็น request เล็ก จึงไม่ชน statement timeout ของ Supabase (ต่างจาก "ลบทั้งตารางแล้วใส่ใหม่")

## ⏰ ตั้งให้รันทุกวัน (หลังตัว export ของข้อ 1 ในสายพานมีแล้วเท่านั้น)

**เวลาต้องอ่านจาก `LastWriteTime` ของไฟล์จริงบนเครื่องที่รัน ห้ามอนุมาน** (บทเรียนเดียวกับ auto-r05 · กฎ 0 ใน CLAUDE.md)
```powershell
Get-Item "$env:USERPROFILE\Desktop\run-upload-stock\*R14*102*.CSV","$env:USERPROFILE\Desktop\run-upload-stock\*R05*105*.CSV" |
  Select-Object Name, LastWriteTime
```
ต้องเป็นเช้าวันนี้ทั้งคู่ แล้วเลือกเวลาที่หลังไฟล์ที่เสร็จช้ากว่า เผื่อไว้พอสมควร:
```powershell
$Root = "$env:USERPROFILE\Desktop\auto-adj"          # <-- ที่วางโฟลเดอร์
$Time = ""                                           # <-- เวลาที่เลือกเอง เช่น "09:15"
$Bat  = Join-Path $Root "run_auto_adj.bat"
if (-not (Test-Path $Bat)) { throw "ไม่พบ $Bat" }
if (-not $Time) { throw "ยังไม่ได้ใส่เวลาใน `$Time" }
$A = New-ScheduledTaskAction -Execute $Bat -WorkingDirectory $Root
$T = New-ScheduledTaskTrigger -Daily -At $Time
$S = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 30) `
       -MultipleInstances IgnoreNew -DontStopIfGoingOnBatteries -AllowStartIfOnBatteries `
       -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 20)
Register-ScheduledTask -TaskName "AutoAdjImport" -Action $A -Trigger $T -Settings $S `
       -Description "อัป R14.102 (LOT/EXP) + R05.105 (ราคา Level 4) ขึ้น Supabase ทุกเช้า (ป็อปอัพปรับปรุงสินค้า)" -Force
```
`-StartWhenAvailable` ปลอดภัย: เขียนได้เลยถ้าไฟล์ยังเป็นของวันนี้ และไม่กระทบรอบนับใดๆ (ไม่แตะ Firestore เลย)

| exit code | ความหมาย |
|---|---|
| `0` | สำเร็จ **หรือ** เนื้อหาเหมือนเดิมจึงไม่เขียน (log บอก) |
| `1` | อ่าน/เขียน Supabase ไม่ผ่าน (ชุดที่ใช้งานอยู่ไม่ถูกแตะ) หรือไม่พบ service key |
| `2` | ไม่พบไฟล์/โฟลเดอร์ หรือ flag ไม่รู้จัก |
| `4` | ด่านไม่ผ่าน (ไฟล์ไม่ใช่ของวันนี้ · หัวคอลัมน์เพี้ยน · แถวน้อย/หด · ไฟล์ยังเขียนไม่เสร็จ) |
| `9` | ไม่พบ Python |

สองไฟล์ล้มแยกกัน · exit ของทั้งรอบเอาค่าที่รุนแรงสุด (1 แล้ว 4 แล้ว 2)

## 🔎 ตรวจสถานะ / แก้ปัญหา

**ง่ายที่สุด — ดูการ์ดในป็อปอัพ 📦 ปรับปรุงสินค้า:**
`Supabase · อัปเดต HH:MM น. DD/MM/YYYY · 42/45 SKU มี LOT`
- มี `⚠️ บอทยังไม่ได้ตรวจวันนี้` = `checked_at` ไม่ใช่วันนี้ ⇒ บอทหรือตัว export เช้านี้ไม่ได้รัน (ต่างจาก R05.106 ตรงที่เวลาตรวจขยับทุกรอบแม้เนื้อหาไม่เปลี่ยน)
- `ยังไม่มีข้อมูลบน Supabase` = ยังไม่เคยอัปไฟล์นั้นเลย
- `โหลดจาก Supabase ไม่ได้` = เน็ต/Supabase/ยังไม่ได้รัน SQL — ป็อปอัพถอยไปใช้ LOT/ราคาที่ 💾 บันทึกไว้ หรือแนบไฟล์เองได้ตามเดิม

**ฝั่ง Supabase:** Table Editor → `adj_meta` ดู `active_gen` · `row_count` · `uploaded_at` · `checked_at`

**ย้อนกลับไปชุดก่อนหน้า** (บอทเขียนของผิดขึ้นไป): ใช้คำสั่ง SQL ท้ายไฟล์ `supabase-adj.sql` — สลับตัวชี้กลับ ไม่ต้องอัปใหม่
แล้ว `Disable-ScheduledTask -TaskName "AutoAdjImport"` จนกว่าจะแก้ต้นเหตุ
